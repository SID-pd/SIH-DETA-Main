## 1. Executive Summary

Prior to launching **Phase 4 (Dynamic ETA Prediction Engine Machine Learning Training)**, a deep cross-database integrity and architectural audit was conducted across all six ingested modules and databases. 

The audit uncovered **5 significant underlying data and architectural issues**, most notably a critical historical station code renaming mismatch that silently unlinks **72,508 train sectional delay records (5.01% of the nationwide 1.44M dataset)** from their station coordinates and platform topology.

This report documents the root causes, empirical evidence, volume of affected records, and the step-by-step remediation plan.

## 2. Detailed Breakdown of Discovered Issues

### 🚨 Issue #1: The Indian Railways Station Code Renaming Anomaly (72,508 Unmapped Records)

#### Root Cause:
Over recent years, the Ministry of Railways officially renamed dozens of major railway stations and junctions across India:
- The **Station topology database** ([`Station-Halt Scraper/data/stations.db`](file:///scratch/home/sid01/SIH-DETA/Station-Halt%20Scraper/data/stations.db)) was sourced from legacy CRIS/DataMeet catalogs that retain **pre-renaming codes** (e.g. `ALD`, `MGS`, `JHS`, `HBJ`, `CSTM`, `FD`, `PBH`).
- The **Historical delay database** ([`Historical-Delay-Records/data/historical.db`](file:///scratch/home/sid01/SIH-DETA/Historical-Delay-Records/data/historical.db)) was scraped from modern eTrain feeds that utilize **post-renaming official codes** (e.g. `PRYJ`, `DDU`, `VGLJ`, `RKMP`, `CSMT`, `AYC`, `MBDP`).

#### Impact:
When joining sectional delay records (`from_station`, `to_station`) with station coordinates (`latitude`, `longitude`, `platform_count`), **1,148 block sections and 72,508 delay records fail to join and are silently dropped** from the ML training set.

### ⚠️ Issue #2: Disconnected Route Stops Databases (`train_stops` vs. `station_halts`)

#### Root Cause:
- In [`Train-Scraper/data/trains.db`](file:///scratch/home/sid01/SIH-DETA/Train-Scraper/data/trains.db), the table `train_stops` contains only **17 records** (stops for a single test train: 12043 Shatabdi).
- Meanwhile, all **420,345 nationwide scheduled train halts** exist inside [`Station-Halt Scraper/data/stations.db`](file:///scratch/home/sid01/SIH-DETA/Station-Halt%20Scraper/data/stations.db) in the table `station_halts`.

#### Impact:
Any module querying `Train-Scraper/data/trains.db` for route stops (e.g. `Weather-Environment/main.py --mode route`) returns 0 stops for 5,208 out of 5,209 trains, causing silent fallbacks to the Delhi–Howrah corridor.

---

### ⚠️ Issue #3: Primary Key Column Name Mismatch (`number` vs. `train_number`)

#### Root Cause:
- In [`Train-Scraper/data/trains.db`](file:///scratch/home/sid01/SIH-DETA/Train-Scraper/data/trains.db), the primary key column in table `trains` is named **`number`**.
- In all other tables (`train_stops`, `station_halts`, `daily_station_delays`, `sectional_delay_records`, `network_incidents`), the column is named **`train_number`**.

#### Impact:
SQL queries joining on `trains.train_number` crash with:
`sqlite3.OperationalError: no such column: train_number`.

---

### ⚠️ Issue #4: Live Journey Telemetry is Static Test Data

#### Root Cause:
- [`Live-Journey-Tracker/data/telemetry.db`](file:///scratch/home/sid01/SIH-DETA/Live-Journey-Tracker/data/telemetry.db) contains only **6 live snapshots** and **704 track points** resulting from a single manual execution on train 12301.
- There is currently no active recurring service or background cron populating real-time kinematic feeds continuously.

#### Impact:
While suitable for real-time demonstration when queried live, this database does not contain historical kinematic telemetry for offline model training.

---

### ⚠️ Issue #5: Silent Exception Swallowing (`except Exception: pass`)

#### Root Cause:
An audit across the Python codebase identified **22 locations** containing `except Exception: pass` or `except ValueError: continue` without logging:
- `Weather-Environment/collectors/station_geo_resolver.py`
- `Weather-Environment/main.py`
- `Network-Anomalies/analytics/historical_anomaly_miner.py`
- `Historical-Delay-Records/scrapers/crawler_watchdog.py`

#### Impact:
Schema and query errors (such as `SELECT code, name FROM stations` failing because the column was `official_name`) were caught silently, causing the code to fall back to dummy mock data rather than raising visible warnings.

## 4. Remediation & Action Plan

To ensure maximum quality and zero data leakage before initiating Phase 4 ML training, the following four engineering fixes are defined:

### Step 1: Deploy Canonical Station Alias Translation Engine
* Construct an in-memory and SQLite-backed alias resolution dictionary:
  `ALIAS_MAP = {'PRYJ': 'ALD', 'DDU': 'MGS', 'VGLJ': 'JHS', 'RKMP': 'HBJ', 'NDPM': 'HBD', 'CSMT': 'CSTM', ...}`
* **Expected Outcome:** Immediately recovers **100% of the 72,508 unmapped sectional delay records**, re-establishing station GPS coordinates, platform counts, and track topology for all major railway junctions.

### Step 2: Unify Route Stops Bridge
* Standardize all route stop lookup functions across `Weather-Environment`, `Live-Journey-Tracker`, and downstream `ETA-Prediction-Engine` to query `Station-Halt Scraper/data/stations.db` table `station_halts` (`420,345 halts`).
* **Expected Outcome:** Route resolution works seamlessly for all 5,208 master trains.

### Step 3: Normalize Column Aliasing
* Create a SQLite view or standard query alias:
  `CREATE VIEW IF NOT EXISTS v_trains_master AS SELECT number AS train_number, * FROM trains;`
* **Expected Outcome:** Eliminates all `no such column: train_number` runtime exceptions.

### Step 4: Harden Error Handling
* Replace all generic `except Exception: pass` blocks with explicit `logger.warning(...)` statements so operational and schema mismatches are captured in debug logs.
